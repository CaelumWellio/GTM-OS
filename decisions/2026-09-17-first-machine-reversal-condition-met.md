# First machine reversal condition met

Date: 2026-09-17
Decision: the reversal condition recorded in `2026-09-16-first-machine.md` fired. Cycle zero could not separate winners from losers at n >= 20 on any tag, so the outbound engine inventory becomes the next machine. The customer-truth machine itself stays built and stays scheduled; it is not rebuilt, paused or retired.
Alternatives: retire the customer-truth pass and unschedule the weekly job; keep the customer-truth pass as the next machine and rerun it immediately on the same cache; declare the hook hypothesis unfalsifiable and stop testing it.
Why: the condition was written against the hypothesis, not against the instrument. The pass is the instrument that returned the answer, and an instrument that reports a null is working, so it stays built and scheduled to keep reading each week. The answer it returned is that no wording separates winners from losers once conversation volume is controlled for, which removes the hook hypothesis as the thing to build on next and leaves the outbound engine inventory as the first machine, exactly as the 2026-09-16 decision said it would. Rerunning the pass is worth doing only once the SDR-history cache covers every closed-deal company, because 99 of the 803 closed deals have no cached timeline today and the deals outside the cache win far more often than the deals inside it, so a rerun on the same cache would return the same biased population. Extending the cache needs the HubSpot private app's emails read scope restored, which is also what currently stops the weekly job producing a digest.
Decided by: Caelum.
Reversed if: the emails read scope is restored and a rerun over the full closed-deal population separates winners from losers at n >= 20 and at least 10 volume-adjusted points across at least two strata, in which case the customer-truth pass returns as the machine to build on.
